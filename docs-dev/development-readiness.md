# 子專案接續開發

整理到「找得到、知道改哪裡、接得上、收得回來」即可恢復各自開發，不必等所有歷史分支、素材與資料夾搬到同一處。

本文件是開工與收尾規則，不是第二份作品清單或即時狀態表。作品從 [README 作品總覽](../README.md#作品總覽) 找；分類、放置與登錄依 [任務庫規則](../learning-tasks/README.md)，本次目標與進度回查對應 issue／PR。2026-09-18 整理驗收的盤點證據集中在 [#95](https://github.com/huansbox/aiden-study/issues/95)，不代表日後的工作目錄永遠安全。

## 新 session 開工：先過四關

| 關卡 | 最少確認 | 沒通過時 |
| --- | --- | --- |
| 找得到 | 從總覽找到作品、來源 repo／path／ref；新作品先依任務庫規則選 app／task／shared | 先補來源或登錄，不憑目前 checkout 宣稱作品不存在 |
| 知道改哪裡 | 分清可編輯來源、產物及重建方式；所需私人原件在本次執行機器可用 | 只暫停需要該素材／重建路徑的改動，不阻擋其他工作 |
| 接得上 | 核對工作目錄絕對路徑、branch、HEAD、遠端與本機未交付資料；和同時工作的任務協調重疊檔案 | 保留原目錄，改用隔離 worktree；來源歸屬不明先查證，不能覆蓋 |
| 收得回來 | 本次需求、驗證方式、預定交付位置明確，登錄與來源說明會一起更新 | 先縮小範圍或補足交付方式，再開始功能變更 |

開工回報保持簡短：本次作品／issue、來源與執行目錄、基線、會修改的範圍、如何驗證；有例外才另列。不需再建立常態人工狀態表。

### 工作目錄與跨裝置

1. 先讀當前目錄的規範，再確認 repo remote 與狀態、更新遠端資訊，讀最新主線的規範。一般新工作從最新 `origin/master` 建立獨立工作分支／worktree；不要在上一個 task 的舊分支順手接新功能。所有工具明確指定新目錄，不能只建立 worktree 卻繼續在原目錄執行。
2. 原有工作若尚未整合，先比對來源；squash 合併不能只看 commit 是否出現在 master，要再查 PR、patch 或內容是否已交付。不自動重送整條歷史分支。
3. 分機器確認工作目錄。GitHub 只知道已推送內容，不知道另一台的未提交檔案、私人原件或正在執行的程序。接手另一端工作，先取得那一端針對本次範圍的最新回報。
4. 同時開發時，各自處理專屬範圍；`docs/registry.json`、`learning-tasks/catalog.json`、`docs/shared/`、`worker/` 與生成索引等共用範圍，指定一個整合者協調合併。不是永久鎖檔，也不新增人工 ownership 清單。合併前更新基線並重跑受影響驗證，不能只因修改不同子專案就假定沒有衝突。
5. `untracked`／`ignored` 不等於垃圾。私人題庫、回放音檔、進度備份、候選素材、`.scratch/`、`.local/` 與本機排程狀態可能不在 Git；保留原處，若確需搬移，先逐項確認用途與可恢復來源，再另取得授權。不要整批複製或清理。

排程與手動開發亦須分開。接續 Native Camp 先讀 [weekly automation SOP](../learning-tasks/shared/nativecamp/weekly-automation.md) 並核對執行端的目前狀態；不要把排程的工作目錄當一般開發目錄，也不因功能暫停而自行開關排程或刪除付費請求紀錄。

### 合理例外不擋全 repo

- **外部 repo**：按登錄的 repo／ref 回到其來源開發；本 repo 保留入口即可。要改外部 repo，仍需在該 repo 確認本機與遠端狀態，不能把本次 aiden-study 盤點視為外部工作目錄也已驗收。
- **主線外故事網站**：從總覽的分支入口讀來源，正式整合前不能把 branch-only 成果當成主線檔案。需要接續時，先在隔離環境比對最新主線與既有來源，再決定選取哪些改動；不阻擋注音、英文等其他工作。
- **私人素材**：clone 不含私人原件是設計，不是缺檔 bug。沒有原件的機器仍可做不需它的程式修改；需重建私用題包／PDF／老師錄音時，必須在具備合法來源的環境執行。正式孩子資料不是測試 fixture。
- **歷史工具**：先讀該作品的目前重建說明，不能看到 script 就重跑。例如 [Native Camp 9/15 首堂](../learning-tasks/nativecamp-review-pilot/README.md) 的 SAPI CLI 不是現行製作入口；修改該堂題文需先補安全的文字重建方式，不影響新增課程與其他 App。
- **已豁免人工驗收**：保留原決定與驗證界線，不把已免除的 iPad checklist 或尚未發生的首次週排程重新當成所有子專案的開工門檻。新需求確實受影響時，才針對改動補驗。

## 收尾：讓下一個 session 能接手

- 新 task 從建立時就落在 `learning-tasks/<task>/` 並登錄；App 使用 registry；來源、產物、必要私用前提與重建方式寫在作品自己的入口。可共用經驗依任務庫的重用規則收進 shared，不另複製整份原始任務。
- 改登錄時只改唯一來源，執行 catalog builder 更新產物；不手改 README 清單或白板日期。不因臨時停工就批次改 `paused`，也不以 App 啟用、commit 時間冒充工作完成。
- 跑本次適用的測試、來源／產物一致性與獨立 review；修完 finding 後重跑。程式改動涉及同步或身份時，用 [本機隔離驗證入口](../README.md#本機啟動)，不得為整理任務重置孩子正式進度。
- 需交付到主線的工作，以 PR 整合及相關 CI／發布核對作為完成證據；單純 push 分支不等於完成。未完成部分留在對應 issue／PR，交代來源、限制與下一步；主線外作品維持明確登錄，不能只留聊天記憶。
- 不要求刪掉已合併 worktree 才算完成。清理歷史目錄是另一個可選任務；先確認沒有唯一來源、未追蹤資料或仍在使用的排程。

### 既有自動檢查

在 repo 根目錄執行：

```sh
node scripts/build-work-catalog.mjs --check
node --test "tests/*.mjs"
uv run pytest
```

修改登錄後先執行 `node scripts/build-work-catalog.mjs` 再 `--check`。需要完整 Git 歷史；macOS 若測試受 `/var` 與 `/private/var` 暫存路徑差異影響，依[白板維護說明](parent-whiteboard.md)使用 `env TMPDIR=/private/tmp node --test "tests/*.mjs"`。

現有 catalog tests 會拒絕漏登的 `learning-tasks/<task>/`、重複 ID、不合法來源／狀態等，CI 已執行它們。不會發現從未推送、未按規格落檔或從未登錄的任意外部作品；這部分仍靠上述開工回報與跨裝置核對，而非再維護一張手動清單。

通過以上條件代表可以承接下一項已授權需求，不會自動喚醒舊任務、恢復功能開發或改變排程。
