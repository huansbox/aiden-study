# 動畫教學短片：這次的經驗與調查結果

2026-11-13 第一次做「程式畫動畫＋配旁白」的教學短片。這份是原始紀錄，還不是 SOP；哪些要變成固定流程，等家長復盤後再決定。標「家長定案」的是家長明講的決定，其餘是製作時的判斷或實測。

## 1. 流程順序與每步的改動成本

| 步驟 | 做什麼 | 改動成本 | 這次的實際情況 |
| --- | --- | --- | --- |
| 1 講法 | 用什麼道理說明、順序怎麼排 | 零，只是討論 | 第一版沒對齊就定了「撕角」，做完才被否決 |
| 2 逐句稿 | 每句旁白＋那句話時畫面在做什麼 | 幾分鐘 | 第一版直接寫進程式，家長沒看過；第二版先給另一個模型審，再給家長看 |
| 3 旁白聲音 | 每句一個音檔，量出長度 | 每句幾秒（線上語音）或約半分鐘以上（本機 clone） | 只重產有改字的句子 |
| 4 動畫 | 每段圖形怎麼動，時間對到旁白句子 | 最高，新講法等於重寫 | 第一部整部重寫 |
| 5 抽格檢查 | 抽指定時間點的畫面拼成一張圖 | 每輪一兩分鐘 | 每一版都靠它抓到版面問題 |
| 6 輸出 | 逐格畫、混音、加字幕 | 每部兩三分鐘 | 兩部可同時跑 |

**這次最大的教訓**：講法和逐句稿是純文字，改起來幾乎不用成本；第一版跳過這兩步的對齊，直接做到輸出，結果第一部整部重做。之後應該在步驟 1 和步驟 2 各停一次給家長確認，確認後步驟 3 到 6 一口氣做完。

**家長定案的流程要求**：逐句稿寫完，先讓 GPT 獨立審查，由主 agent 決定是否調整，再給家長看。

## 2. 開工前要先問清楚的事

這三件第一版都是做完才知道，每一件都會改到講法：

- **觀眾是誰、已經學過什麼**。一開始說「8 歲」，後來定為「小學四年級、已學過角度」。差別很大：前者要先教什麼是角，後者可以直接用「轉半圈＝180 度」。
- **結論放哪裡**。家長定案：要帶走的結論先講。第一版是先問「猜猜看」、做完實驗才給規則。
- **要「看到現象」還是「說明理由」**。家長要的是理由。撕角拼成直線只是示範，沒有回答為什麼。

## 3. 講法調查：為什麼三角形內角和是 180 度

| 講法 | 內容 | 有沒有說明理由 | 結果 |
| --- | --- | --- | --- |
| 撕角拼直線 | 三個角撕下來，尖端對齊排成一直線 | 沒有，只看到現象 | 第一版採用，家長否決 |
| 摺紙 | 頂點往底邊摺，三個角摺到同一點 | 沒有，是撕角的變體 | 未採用 |
| 拖動頂點、壓扁 | 度數即時變、總和不變；壓到底變成直線 | 沒有，是直觀感受 | 第一版採用，第二版刪除 |
| 長方形切一半 | 四個直角 360 度，對角線切成兩個一樣的三角形，各 180 度 | 有，但只涵蓋直角三角形 | 家長定案：當第一階段，刻意用特例快速得到結論 |
| 鉛筆轉半圈 | 鉛筆在三個角依序同方向各轉一次，回到底邊時頭尾顛倒 | 有，任何三角形都成立 | 家長定案：當第二階段 |
| 沿三角形走一圈 | 轉彎共 360 度，三個轉角共 540 度，相減得 180 度 | 有 | 未採用：要算 540−360，內角和轉彎角容易混 |
| 平行線 | 過頂點畫平行線，兩個底角搬上去排成直線 | 有，是國中的正式證法 | 未採用：要先接受平行線夾角相等，四年級還沒學 |

家長定案的結構：先講結論 → 特例（長方形）快速得到結論 → 自然帶出疑問「沒有直角的呢？」→ 一般說法（鉛筆）。旁白裡不說「第一個方法、第二個方法」，讓疑問自己把兩段接起來。

兩個製作時要留意的細節：

- 長方形那段，關鍵是「四個角全部分給兩個三角形，沒有多也沒有少」這一句。少了它，360÷2 就只是剛好。
- 鉛筆在第二個角轉完後，是倒退著滑到第三個角。家長定案：旁白要講明「倒退著滑」。

第二部（三邊長）的講法沒有被挑戰：手臂牽手（太短／剛好扁掉／夠長）、直直走最近、開關門說明相減。只把開頭改成結論先講。

## 4. 教學設計上用到的做法

- 旁白負責講，畫面負責動；螢幕上只放關鍵字和算式，不把旁白整句打出來。
- 同一個東西全片同一個顏色（例如三個角固定紅藍黃，最長的棒子固定藍色）。
- 每段左上角有編號和小標題，方便暫停討論。
- 沒有背景音樂，只在關鍵時刻有短音效。
- 需要孩子想的地方（挑戰題）留 3 秒空白。
- 片尾請孩子動手做一次。

這些是製作時的選擇，還沒有孩子實看的回饋可以驗證。

## 5. 技術做法與踩到的坑

**做法**

- 用 Node 的 `@napi-rs/canvas` 逐格畫 1920×1080 的畫面，直接把原始像素餵給 ffmpeg 編碼。不開瀏覽器，一部兩三分鐘。
- 時間軸由旁白長度決定：每句音檔先量長度，句子依序排開；動畫的每個時間點都寫成「某句開始後幾秒」。改旁白後畫面會自動跟著移動。
- 某句話比它要配的動作短時，在那句後面加停頓（`gap`），不要硬把動作壓快。這次鉛筆「滑過去再轉」兩個動作就需要 1.0 和 1.5 秒的停頓。
- 旁白音檔頭尾的靜音先裁掉，句子之間的間隔統一由腳本決定。
- 字幕做成 MP4 內可開關的字幕軌，不燒進畫面。

**坑**

- **字型集合檔只會註冊到第一個字體**。macOS 的圓體和蘋方是 `.ttc`，canvas 套件只認得裡面第一個（港版蘋方、簡體圓體），結果中文全部變方框。解法是先用 fonttools 把需要的字體拆成單獨的 `.ttf`，放在不進 Git 的快取。
- **抽格檢查抓到的都是算不出來、要看才知道的問題**：文字互相蓋住、角的色塊畫到三角形外面、標籤被別的圖擋住、動畫還沒做完下一句就開始。每一版都至少抓到三四個。
- **`learning-tasks/catalog.json` 不能用程式整份重寫**。它有手排的單行陣列，用 `json.dump` 會把整個檔案的排版改掉。只能用文字插入，再跑 `node scripts/build-work-catalog.mjs --check`。
- **做不到的事**：agent 看得到畫面，聽不到聲音。發音、語氣、節奏只能由人聽。

## 6. 旁白聲音的調查

| 方式 | 狀況 | 結論 |
| --- | --- | --- |
| macOS 內建 `say` | 這台只有精簡版的臺灣中文聲音（美佳） | 沒用，機械感重 |
| Microsoft Edge 線上語音（`edge-tts`） | `zh-TW-HsiaoChenNeural` 正常；`zh-TW-YunJheNeural` 當下回 `NoAudioReceived`，沒追原因 | 目前的預設。免費、快，但走非官方介面，要連網 |
| OpenAI 語音 | 這個 repo 的英語任務在用，金鑰由 1Password 注入 | 沒用：agent 的子程序連不上 1Password，要家長自己在終端跑 |
| 本機 IndexTTS 2.0 clone 家長本人聲音 | huansbox/phy-redraw-video 已定案的做法，這台 Mac 有現成的 runtime、模型和參考音 | 這次另外產了一版給家長比較，實測見下 |
| ElevenLabs | phy-redraw-video 測過 | 那邊已否決：像不像本人較差、要持續付費、聲音要上傳 |

**phy-redraw-video 那邊已經有的結論**（來源：該 repo Wiki〈Voice cloning〉的「Mac 輪」一節與 issue #65）：

- 中文 clone 選 IndexTTS 2.0，參考音用 MacBook 內建麥克風新錄的一句，約 9 秒。講者 A 是家長本人，任何用途都可以用。
- 模型不認得正體字，送進去之前要轉成簡體。
- 多音字可以把整個詞換成大寫拼音加聲調數字來鎖定讀音（例如 `YUAN2CHANG2`）。那邊的原則是先生成、聽到念錯才加。
- Apple Silicon 可以跑，但合成時間大約是音檔長度的 3 到 8 倍；大量生成用 Windows 的顯示卡較合適。
- 那個 repo 另有一套「試聽 → 家長核准 → 鎖定音檔」的流程，因為同一句每次合成的波形不會完全相同。

**這次實測（M5、16GB，2026-11-13）**

- 50 句、合計 247 秒的旁白，合成共花 1257 秒，約是音檔長度的 5 倍；第一句含暖機花了 170 秒。
- 本人聲音講得比線上語音快約 15%：第一部 1 分 41 秒（線上語音版 1 分 56 秒），第二部 2 分 44 秒（3 分 09 秒）。
- 語速不同會讓動畫對不上：動畫時間原本是照線上語音寫的「某句開始後幾秒」，換成較短的句子後，有的動作還沒做完下一句就開始，有一段甚至整個沒出現。解法是輸出時逐句把新旁白的時間對應回原本的時間，動畫照原設計播放、只是跟著每句的實際長度快一點或慢一點。換任何聲音都不用改動畫。
- 沒有人聽過這一版，讀音表裡的詞有沒有念對、有沒有別的字念錯都還不知道。

**這次和那邊做法的差異**

- 這次沒有家長試聽就直接產完整部，因為家長不在場，目的是讓家長早上能直接比較兩版。
- 讀音表先放了十幾個有風險的詞（主要是「長」「還」「朝」「倒」），沒有等聽到念錯才加。理由同上：沒有人能先聽。
- 這個 repo 是公開的，所以 clone 的旁白和影片放在私人 Dropbox，不進 Git。

## 7. 還沒驗證、等家長決定的事

- 兩種旁白都沒有人從頭聽過。
- 孩子還沒看過。
- 旁白要用線上語音還是本人聲音。
- 這份紀錄要怎麼變成可重複使用的 SOP，以及要不要搬到 `learning-tasks/shared/`。依任務庫規則，同一做法在第二個不同任務實際重用後才整理到 shared。
