# 幼兒現場觀察任務卡：設計與驗證經驗

> 來源：2026-08-13～14「新竹動物園小小探險」任務卡的多輪設計、使用者覆核與成品驗證。案例成品見本目錄 [`README.md`](README.md)；本文記錄可供後續場館或旅行任務再次驗證的方法。

## 結論

給 5～6 歲孩子的現場任務，不應設計成待辦清單或知識考試，而要做成一組彼此獨立、隨時可以收起的觀察邀請。好題目同時具備三件事：孩子能從眼前或卡片取得線索、不能靠單一突兀差異秒答、動物沒出現時也不會留下「失敗」感。

圖卡不是把正解藏起來，而是替孩子搭一座剛好能走過去的橋。線索太少會變成猜題；正解太醒目則只剩找不同。

## 1. 先定義「可以中止」，再設計題目

現場有高溫、遮蔽、動物休息、孩子疲倦與行程改變等不可控因素。若成功定義是「找到所有動物、完成全部卡片」，卡片會從探險道具變成壓力來源。

可重用的做法：

- 每張卡獨立，不設必做順序、完成百分比或剩餘張數。
- 一題只抓 30～90 秒；線索看不清就收卡，不原地等待動物配合。
- 區分「觀察成功」與「完整作答」。例如只看到鼻子、沒看到尾巴，仍算發現一項，不要求猜三選一。
- 地圖只用來選下一個方向，不把站點畫成需要逐一打勾的 checklist。
- 收尾卡允許只說、只指、畫一筆、貼一張票根，甚至不留下紀錄。

## 2. 適中難度靠交叉干擾，不靠生僻知識

三選題最穩定的結構是兩項視覺線索交叉排列。假設正解同時具有 A、B：

- 選項 1：A + 非 B
- 選項 2：非 A + B
- 選項 3：A + B

如此只看 A 或只看 B 都會剩兩個候選，孩子必須合併線索。河馬腳題以「四趾」和「寬鈍趾甲」交叉，長臂猿手題以「長彎四指」和「低位拇指基部」交叉，就是這個結構。

常見失效：

- 只有一張有尾巴、只有一張有長爪：名義上有兩項線索，實際仍可用唯一突兀特徵秒答。
- 錯誤選項畫得像畸形或尺寸特別小：孩子靠「哪張怪怪的」作答。
- 題名直接說出線索，例如「長鼻浣熊」「長臂猿」：成人唸標題時已洩答。面向孩子的標題宜中性，物種名可留給成人區。
- 同類題答案位置固定：即使每題本身成立，整副卡仍會產生「reference 題都選 1」的捷徑。答案位置要在 deck 層級一起檢查。

## 3. Reference 配對可取代先備知識與等待行為

當特徵難以從現場穩定看到，可在卡面上方放一張 reference，讓孩子從圖中取得線索，再到三個同視角放大選項配對。這比成人先教「狐獴有四趾長爪」更像觀察，也不需等待動物露出腳底。

Reference 題有四項硬條件：

1. reference 與選項使用相同視角與同一種部位。
2. 提示文只說觀察順序，例如「先數有幾根，再看前端形狀」，不能寫出答案特徵。
3. 三選的尺度、位置、明暗與裁切一致，只改指定變項。
4. 現場動物只算加碼發現；卡片本身必須能完成。

## 4. 動物學正確不等於可作為題目

穩定解剖特徵與可能出現的姿勢要分開。長臂猿拇指在不同移動方式中可能位於枝條不同側，因此「拇指繞枝方向」不能設成唯一正解；應改考穩定的手指長度、彎曲度與拇指基部位置。

同樣地，理想化腳部構造不能直接宣稱是真實泥地足印。河馬有四個承重趾是穩定事實，但泥地、步態與踩踏深度會改變印痕完整度。題目最後改為同視角「實腳配對」，避免教出錯誤因果。

設計時應逐題問：

- 這是穩定外觀，還是只在某個姿勢／年齡／角度出現？
- 孩子能在安全距離看見嗎？
- 正解是否暗示「一定會如此」？
- 若現場不是卡片角度，能否自然跳過？

## 5. 圖像公平性要寫成 production constraint

只寫題目概念不足以保證成品公平。生成與裁切時必須鎖定：

- 同一 canvas、外輪廓、視角、尺度、位置與明暗。
- 不出現頭、背景、棲地、姿勢或完整物種輪廓等額外答案線索。
- 每張只改題目指定的兩個變項。
- 需要計數的趾、指、腳須互不遮疊且完整留在框內。
- 選項邊緣要留白；拼接圖裁切後特別檢查是否夾入鄰圖碎片。

AI 產生三合一圖後，不能假設等分裁切就是乾淨選項。本案例多次出現鄰殼、殘爪或弧形碎片；這些小瑕疵會被孩子誤認成第五趾、第二條尾巴或殼緣特徵。最終 PDF 必須放大檢查每個選項邊界。

## 6. 地圖與照片式插畫的資訊量要分工

地圖圖示只負責選站，不應預告後面題目的答案。例如虎站圖示若先畫出完整身體條紋，後面的虎紋題就失去觀察價值；河馬圖示若露出眼耳高度，也會先洩題。

做法是讓地圖保留可辨識性，但遮住或裁掉後續考點：虎只露頭肩、河馬只露寬吻、長臂猿以枝葉遮住手臂比例與尾部。地圖負責「去哪裡」，題卡才負責「看什麼」。

需要表達真實物件的插畫應與整副卡畫風一致。普悠瑪由簡化 SVG 改成寫實灰階插畫後，又把火車與鐵軌合併生成，才能讓輪軌接觸、陰影與透視一致；把兩張不同透視的素材硬疊在一起，局部再精細仍會顯得漂浮。

## 7. 兩階段 review 比一次總審更省工

先審規格，再產圖；不要在核心題型未通過時重畫。

### Gate 1：題目規格

- 動物特徵是否正確、穩定。
- 5～6 歲是否需合併線索，而非秒答或靠先備知識。
- 是否可在 30～90 秒完成，不要求特定姿勢。
- 動物沒出現時能否自然中止。
- 整副卡是否有答案位置規律。

### Gate 2：成品

- 逐張放大看裁切、殘片、趾／腳數、外輪廓與對齊。
- 在實際列印尺寸確認細節仍可辨識。
- render 每一頁 PDF，不只看 HTML 或原始圖。
- 自動檢查圖片載入、卡片數、每頁張數與 overflow；視覺檢查不能由自動檢查取代。

## 8. PDF 與 repo 歸檔

可重印素材應同時保存：

- 可編輯的 HTML/CSS 真相源。
- HTML 實際引用的高品質圖資。
- 最終 PDF。
- Imagegen prompt 與重要設計決策。
- 一張代表性 preview，方便在 GitHub 快速辨認成果。

不要把每輪 render、未採用圖、重複 source master 全部塞進 Git；Git history 不是生成暫存區。若 PNG 很大，可改存高品質 WebP，再由 HTML 重新輸出 PDF並做逐頁視覺驗證。完成且沒有後續待辦的家庭素材，不應新增 issue、寫進執行中 `HANDOFF` 或 roadmap；用獨立目錄、README、commit 與 branch／PR 保存即可。

## Takeaways

- 把成功設計成「有一個發現」，不是「完成全部」。
- 難度靠兩項線索交叉，不靠冷知識或唯一醒目差異。
- 卡面 reference 能讓任務自足，也能避免等待動物配合。
- 只用穩定解剖特徵；可能姿勢不能當唯一正解。
- 題目公平性必須落成視角、尺度、裁切與可數性的產圖規格。
- 先過規格 Gate，再產圖；成品還要再過實際尺寸 Gate。
- Repo 保存可重建成果與可重用知識，生成中間檔留在 Git 之外。
