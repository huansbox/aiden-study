# 兒童閱讀心智圖：可重用做法

適用於已提供文章、由 9 歲孩子用 iPad 選詞、最後抄到作業本的一次性閱讀任務。已在 [司馬光閱讀任務](../reading-mind-map/README.md) 與 [悠閒午後](../leisure-afternoon/README.md) 使用；這裡保存共通做法，文章內容與各次驗收仍留在各任務。

## 每週交付素材

每週換一篇新文章，孩子首頁的「心智圖」預設開日期最新的已發布文章；「過去文章」可選舊篇，選取不改變下次預設。家長提供文章全文或依頁序的清晰照片，包含原題與所有正文；老師另有格式要求、必留重點或上次批改時再一併附上，沒有就省略。照片看不清或缺頁才補問，不要求家長先整理主枝、選項或段落摘要。

可直接複製以下文字並附上材料；若對象不同，把孩子名字換掉：

> 請替煦誠製作本週閱讀心智圖。文章全文或清晰照片附在這則訊息，老師要求／回饋有的話也一起附上。沿用目前的大字注音、選詞引導與完成後抄寫版，依新文章安排主枝並保留各段必留重點。完成檢查後，直接發布並加入文章索引，讓煦誠的「心智圖」預設開這篇新文章。

這段交付文字包含發布與更新文章索引的授權；同一次工作已有授權時直接沿用，不逐步重問。若本次只要預覽，將最後一句改為「先完成本機預覽」。新文章仍由 agent 讀材料、製作互動內容；家長後台沒有上傳文章後自動生成的功能，也沒有每週自動執行排程。

## 每週製作與換入口

以下由 agent 完成，不另交一份每週真機驗收表給家長。

1. **找素材、保留重點。** 先讀 [任務索引](../README.md)、兩篇任務 README 與 [老師回饋／段落對照](../leisure-afternoon/source/coverage.md)，再讀本週材料。依 [任務資料夾規格](../README.md#任務資料夾規格) 建立新任務並加入索引；在新篇的 `source/coverage.md` 簡記各段必留內容、可取捨例子及老師要求。主枝數與名稱由新文章決定，不固定套四枝或五枝。
2. **製作獨立文章。** 沿用下方的注音、選詞、短詞與抄寫版做法；參考〈悠閒午後〉保留每篇自己的 `source/`、`build.mjs`、部署目錄與 LocalStorage key，不覆蓋舊文章的來源或選擇進度。沿用 [回首頁處理](../../docs/shared/task-home.js)，讓從孩子首頁進來的文章保留 `child`，返回同一個孩子。文章是一次性 task；在 `docs/registry.json` 的 `mindMaps` 索引登記 `id`、`title`、`date`（YYYY-MM-DD）、`path`（站內相對路徑），不登記成新 app。列表依日期由新到舊排序，不依檔案列出順序；日期為本次文章的作業日期，同日文章沿用索引順序。
3. **檢查後交付。** 執行新篇的 build 與 `--check`；參照 [既有內容測試](../../tests/test_leisure_mind_map.mjs) 檢查每種合法選法保留必填重點、選詞限制、字數、讀音、壞存檔與來源／產物一致。執行該篇及受影響的測試；若改到共用讀音或首頁銜接，同時跑 [舊篇](../../tests/test_mind_map.mjs)、[家庭設定](../../tests/test_family.mjs) 與 [入口連結](../../tests/test_family_client.mjs) 相關檢查。用瀏覽器走完選詞、回改、重新整理與抄寫版，按下方尺寸檢查字、注音、連線與按鈕可見；發布時仍須通過 repo CI。
4. **文章與索引一起發布。** 執行 `node scripts/build-home-release.mjs` 更新首頁發布版本，讓已開啟的首頁能發現新文章。依當次授權一併發布文章、索引與首頁版本，核對正式頁面、內容、manifest、字型與 CI。從孩子首頁開啟最新文章，再按「回學習首頁」，確認回到原孩子；「過去文章」可開舊篇，返回後預設仍是新篇。不需每週改雲端家庭設定；家長後台只控制是否顯示心智圖。若本次未授權發布，先交付預覽，再只確認尚缺的發布授權；正式入口保持原文章。
5. **留來源，結束本週任務。** 補齊新篇 README、段落對照、實際驗證結果與代表性完成圖，將索引標為已完成。保留舊篇來源、再製資訊與索引，使「過去文章」能繼續開啟；各篇原有選擇進度不刪除。略過的真機或列印項目如實記錄，不記為通過，也不自動列成下週待辦。

家長平常可自行在「心智圖」勾選各孩子是否顯示，最後按「儲存全部設定」。後台顯示最新篇名，不再要求家長填網址。新的文章選詞與互動內容仍需先製作；機制與回首頁行為見 [已發布的首頁機制](../../docs-dev/family-uiux-v2.md)。

## 孩子怎麼操作

- 中心主題向外連主枝，再連短詞。每次只引導一個重點，選後即時長出圖；完成後顯示適合抄寫的完整圖。
- 選項是有文章依據的短詞，不計分。提示預設收合，忘記時能回頭讀；成人可先請孩子說明理由。
- 每個短詞約 3～5 字。兩次任務都用 60 字作程式檢查上限，含中心與枝名；孩子畫面不顯示「抄寫 N 字」。這是目前篇幅的限制，不能為湊字數刪掉重要段落。
- 有原題就用原題；照片沒有標題時，需明示孩子選的是摘要名稱，不冒充原題。

## 案例差異不能省略

舊作業採四條主枝，老師後來另補「貢獻」。這次〈悠閒午後〉因此安排五枝，並把「詩與照片的關係」「共同心意」獨立保留；不是把任何文章都硬塞進五枝。下次先讀 [老師回饋與段落對照](../leisure-afternoon/source/coverage.md)，依新文章決定哪些內容必留、哪些例子能讓孩子取捨。本次保留四種詩景的成組選項，也只適用於該段內容。

## iPad 與注音

- 橫向以左側選題、右側預覽；完成後放大整張圖。依實際可用高度排版，保留手動縮放。展開提示時允許捲動，不裁掉內容。
- 選題文字約 22px、標題約 26px，完成圖約 24～26px；選項與下一步按鈕至少 48px。字型含右側注音，不能只用中文字寬度估算。
- 字型唯一資產為 `docs/assets/fonts/BpmfZihiSans-Bold.ttf`（約 5.34 MB）。[來源與授權](../../docs/assets/fonts/README.md) 隨站保留，首次下載失敗要顯示退回中文字的提示。
- `docs/mind-map-reading.js` 處理顯示用多音字選音；新文語境額外規則放該任務內容中。〈悠閒午後〉另校正相通、相機、一行詩、看得懂、重新。不要把顯示用選音符號寫進選項或存檔，也不要改共用規則而誤傷舊文章。
- SVG 連線用實際文字盒量測，字型載入或畫面尺寸改變後重算。檢查文字盒相交與連線靠近文字的情形，不能只看一張桌面截圖。

## 來源、進度與部署

舊作業的唯一來源仍在 `docs/mind-map.*`。新任務沿用〈悠閒午後〉的組織方式：`learning-tasks/<task>/source/` 保存可編輯來源，`build.mjs` 產生 `docs/<entry>/` 部署檔；來源、產物一致性納入 Node 測試。這是檔案編排參考，兩個頁面尚未抽成共同應用程式。

每篇使用不同的 LocalStorage key；完成狀態還原前要過選項白名單及必填數量檢查。心智圖的選詞進度不接學習平台同步；首頁顯示由每個孩子的 `mindMap.enabled` 決定，最新與過去文章由 `registry.json` 的 `mindMaps` 索引決定。舊家庭設定的 `title`／`url` 暫留以相容既有 Worker，但不再決定新版首頁的文章。直接開文章可用自己的 manifest；從孩子入口進來時沿用平台 manifest，並保留回到該孩子首頁的連結。Safari、主畫面 App、localhost 與正式網域的進度不保證共用，換入口後不能宣稱舊選擇會自動搬過去。現況沒有離線功能。

正式站為 `https://kids.linshuhuan.com/`，GitHub Pages 發布 `master` 的 `docs/`。原照片不公開入庫；保留必要摘要、段落對照、來源與一張代表性完成圖即可。上線後核對頁面、內容、manifest、字型與 CI，不靠本機預覽判定已發布。

## 驗證界線

兩篇既有任務已驗證選擇流程、回頭修改、重新整理還原、選項限制與字數，均做橫直向瀏覽器尺寸檢查。新任務沿用 1024×650、1024×768、1180×720、768×1024 與 390×844；較矮的 1024×650 用來檢查 Safari 留給頁面的空間。這是 agent 的版面檢查，不要求家長每週逐項操作真機。

這些是瀏覽器模擬尺寸，不等於 iPad 真機驗收。老師已批改舊作業可證明成品曾抄寫，不能據此補稱真機觸控、主畫面 App 或列印都測過。各篇記錄實際測過與略過的項目；〈悠閒午後〉已依使用者決定略過額外真機與列印驗證，不列待辦。
