# Native Camp 課後複習製作 SOP

適用對象：已有一些英文基礎、由家長陪同的小孩。以已發布的 `2026-09-15` 課程為第一份基準，並由 `2026-09-14`、`2026-09-16` 兩堂Edon課程重用；不代表已驗證長期學習成效。SOP與模板沿用本入口，兩堂實際共用的建置／音訊核對工具放在 [shared/nativecamp](../shared/nativecamp/)。

## 下次怎麼開始

家長提供課程日期，以及已登入可讀取的課程回放／音檔／逐字稿／教材線索；有老師要求或想加強的地方再補充。不必先自行整理完整逐字稿。

1. 複製[單堂設計模板](templates/lesson-brief.md)，填入本堂資料。
2. 依下列流程核對來源、選概念、設計題目、製作音訊、驗收。
3. 用[本堂填寫範例](lesson-example-2026-09-15.md)校準粒度；實際題目與答案以題包為準。
4. 新課要進網站前，先完成「目前程式支援範圍」所列的接入工作，保留已發布課程。

可直接交給下一個任務的指令：

> 請依 learning-tasks/nativecamp-review-pilot/lesson-sop.md，使用 templates/lesson-brief.md 設計這堂 Native Camp 的課後複習。課程日期：〔填寫〕；材料：〔課程頁或本機檔案〕；補充：〔可省略〕。先核對來源及目前程式，再沿用已定案的完整句題型、句首、音訊、評級，以及完成收起／另做每週新題的規則。把不確定的學習判讀明示，保存可重建來源與驗收證據。接入網站及發布依本次已授權範圍執行，保留舊課與進度。

## 不變的設計標準

| 項目 | 標準 |
| --- | --- |
| 學習範圍 | 依本堂已教過的重要內容選概念，不設2–3個上限，也不為湊數加題。每個概念要能用一句話說出「孩子要會什麼」。 |
| Try it | 每概念依序 Build（完整句組句）、Change（依新條件變換句子）、Fix（找出並替換一個錯字）。前兩題通常1個、最多2個合理混淆字；不加入未教語法當陷阱。答案有明確判準，不要求打字或長篇閱讀。舊題 ID、題意與首次紀錄保留。 |
| Say it | 孩子先說，再按 Show answer 對照。問題限定情境與目標句型，列示範及合理替代答案；不做自由聊天或自動發音評分。 |
| 變體 | 每概念各準備3題 Try it、3題 Say it。Try 2 必須帶來實際判斷，例如單複數動詞、主詞、肯定／否定、情境成立與否或語序變換；不連續只換名詞／數字。Try 3 是補強，不提高難度。三題是可用份量，不是每回必做三題。 |
| 孩子文字 | 全英文、短句、熟悉單字；必要時用 Lucide／現有圖示輔助，無中文、emoji、宣傳標語或重複操作說明。家長文件可用正體中文。 |
| 圖像 | 一個圖示代表一個物件，數量與答案一致；要理解的情境直接可見，不需要另開教材。 |
| 句型提示 | 放在圖片／問題下方的作答區、Show answer 上方，與題目同字級、深色。只出現一份，揭曉後保留供對照；不是輸入框。 |
| 模式分工 | Try it 透過排列／變換練完整句，Say it 由孩子口說完整句。若本題測選詞，提示和問題語音不能先供應答案；不能把本堂的固定提示機械套到所有新概念。 |
| 家長資訊 | 詳細首次表現與口說評級在後台。孩子完成頁只看該模式；Preview questions 可看所有題目且不寫入學習紀錄。 |
| 再練 | 完成課程收進 Finished，不再隔天回舊課補題或輪用舊題；另製 Weekly Review 新題。保留首次結果與既有 reviews 歷史，不把訂正成功改算首次答對。 |

本堂句型範例：is/are 用 `There …`，odd/even 用 `___ is ___.`，too many 用 `… too many …`。too many 在本堂 Say it 是指定造句材料；若新課改測 much／many 的選擇，就須重新設計提示，不能先填好正確詞。

## 1. 取得來源並確認證據

- 先確認課程日期、材料對應同一堂、回放長度及可取得內容。從已授權頁面取得音檔後，檢查格式、大小、SHA256與完整解碼；下載連結可能過期，不把簽章URL當永久來源。
- 原錄音、詳細逐字稿、私人頁面節錄存入該堂來源目錄的 ignored 路徑；先確認 `.gitignore` 生效。公開文件只留足以回查的時間範圍、來源類型與去識別摘要。
- 網站逐字稿是線索。與錄音／教材核對關鍵片段，尤其是「誰說的」「老師有沒有先提示」「孩子是否只是跟讀」。來源不一致就標未確定。
- 先檢查聲道；本堂左側主要為老師只是本檔抽樣結果，下一堂必須重查。混音 ASR 可能漏掉小聲回答，不把漏字直接判為不會，也不拿 ASR 成敗評發音。
- 每個候選概念填證據表：來源時間／教材位置、可觀察表現、提示程度、確定度、是否納入。材料不足時仍可針對已知課程內容設計「確認題」，但不能宣稱孩子已有某種錯誤。

## 2. 選概念，再做題目

每個概念先填「目標、容易混淆處、成功判準」，再做六題。優先處理課內重要、需要提示或尚未確定是否能獨立回答的能力。

| 題型 | 製作檢查 |
| --- | --- |
| 選擇 | 一題主要測一件事；選項是合理的對比，不靠字體、顏色、位置或長度提示答案。只有一個正確選項。 |
| 排列 | 點選字卡組完整句，允許撤回；混淆字可留未選，正確字都需選。重複單字各用不同token ID；每個 acceptedOrders 是 tokens 的非空子集。若有多個符合情境的自然排列，全部納入 acceptedOrders，或調整材料消除歧義。 |
| 變換 | 用短卡顯示原句／情境，問題明示新條件；新答案不可原封不動照抄。只改必要維度，不同時增加閱讀負擔與陌生文法。 |
| 修正 | 顯示只有一個錯字的完整句，先點錯字、再選替代字。`sentence` 與 `choices` 都是獨立 token；`answer: {wordId, choiceId}` 只有一組成立，替換後與 `answerText` 相符。可帶字尾標點；正確選項位置交錯。問題音訊不能先念出待判斷的正確詞。 |
| 口說 | 先定可核對的內容與完整句要求，再寫自然短問題、視覺cue、示範答案與可接受變體。圖／語音／答案說同一件事。 |
| 數量或程度 | 用可觀察事實建立判準。本堂 too many 明示容量及物品數，不靠「看起來很多」；其他新概念也要能說明為何答案成立。 |

每題分開記錄 `prompt`（畫面問題）、`instruction`（畫面操作／句型）、`spokenQuestion`（製作語音用逐字稿）、`answerText`（示範答案）。`spokenQuestion` 是製作文件欄位，現有題包不會自動拿它產生音訊；builder／音訊manifest必須明確使用它。

新課的畫面cue可以簡短，語音仍可保留完整指示，例如畫面 `There …`、聲音 `Start with There.`。問題音檔不得念出填空後句子或排列結果。口說固定句型是否透露答案，要按本題目標判斷。

## 3. 評級與複習保持一致

| 情況 | 處理 |
| --- | --- |
| Try it 首次獨立答對 | 記 independent；短鼓勵音後自動念完整答案，按 Continue 才前進。 |
| Try it 看提示後答對 | 記 helped，不能算獨立成功。 |
| Try it 答錯 | 記 incorrect；柔和提示音後念正確示範，可自願再選／排列訂正；首次紀錄不改寫。 |
| Say it | 先回答再揭曉；家長依揭曉前表現選 Got it／With help／Not yet。重聽題目或閱讀預設cue不算額外提示；家長給答案字詞、示範後跟讀不能評 Got it。 |
| 前兩題首次獨立成功 | 該概念本回合可收尾，未出第3題不再要求隔天回舊課補作。Try it 與 Say it 分開判斷。 |
| 前兩題有錯誤／協助 | 本次補第3題；第3題仍不會就示範後收尾，不無限加題。 |
| 未完成／後續複習 | 未完成續作尚未做過的題目。完成後以 Weekly Review 的新題複習，優先首次錯誤／受助概念；較晚成功不抹去首次需加強的依據。 |

新版 Try it 先跨概念做全部 Build，再做 Change，最後只做需要的 Fix；字卡依 question ID 打散，同題操作與重整不換位置。Say it 每回只做一個概念。Done 指本次份量已完成，不等於永久掌握。完成課／週包勾選淡化並折疊進 Finished，孩子不能重新作答，家長仍能預覽全部。舊週包維持原週一至週日設定；新週包依已同步的上週日至週六實際作答選題，見每週規劃 SOP。

Show answer 自動念口說示範；家長選 Got it 後播鼓勵音，再接下一題問題。任務／徽章獎勵只在回合結束畫面出現；單題回饋、暫停或切背景不是回合結束。

## 4. 製作與驗證音訊

- 原音適合時，取老師一句完整、連續且對得上新情境的提問；不逐字拼接，不夾入孩子回答、答案提示或不必要私人內容。不合用就使用一般英文 TTS，無須為了原音改扭題目。
- 一般TTS使用 OpenAI gpt-4o-mini-tts 系列、speed 1.0 預製MP3，不加入慢速／135 wpm指示；Marin／Cedar按課交替，同課問題與答案同聲。已指定聲音寫入製作設定，插入早期課程不重排：09-13 Marin、09-14 Cedar、09-15 Marin、09-16 Cedar、09-17 Marin；首週包 Cedar。孩子重播不呼叫API，key只在製作環境。歷史 Windows 語音與OpenAI試聽比較見[語音比較](../nativecamp-2026-09-16/source/tts-comparison.md)；正式替換後以各堂最新manifest為準，不做聲音複製。
- 每題都要有問題與答案音訊；每次進題自動播放一次，保留 Listen。切題、離頁、進背景取消舊播放；瀏覽器阻擋時可重聽並繼續作答。
- manifest 留製作逐字稿、來源類型、檔名／private ID、bytes、SHA256、duration、codec及解碼結果；原音另記來源hash、聲道與起訖。
- 每個音檔完整解碼、檢查靜音／截斷，核對關鍵單字、數量與答案；ASR抽查、人耳驗聽、桌面播放、iPad播放分開記錄結果，不互相冒充。
- 私人原音只經家庭授權端點；public題包只引用 `{private: "clip-id"}`。一般TTS可隨原創題目放在public audio；原錄音、私人逐字稿與原音base64不進Git。

## 5. 新課檔案與目前程式支援範圍

新的一堂以 `learning-tasks/nativecamp-<lesson-id>/` 保存來源、設計文件與驗收資料，依[任務登錄規則](../README.md) 加入 `learning-tasks/catalog.json`，系列沿用 `nativecamp`，再執行 `node scripts/build-work-catalog.mjs` 產生索引與白板；延用同一個 `docs/nativecamp/` App，不再註冊另一個App。只建立實際需要的目錄與成果；紙本不是每堂必做。

| 項目 | 新課製作方式與限制 |
| --- | --- |
| Lesson | 新的唯一lesson ID，日期欄位用 YYYY-MM-DD；同日多堂可用日期加短suffix區別ID。保留舊lesson JSON及舊ID。 |
| Concept／question | ID以小寫英文或數字起頭，其後可含連字號，最長80字元；同一題包內concept／question ID不得重複。已發布ID不得換成另一種題意／答案，也不任意重排已作答課的三題順序，以免影響待複習題。 |
| 音檔 | 跨課檔名加lesson ID，例如 `audio/2026-09-22-is-are-try-1-q.mp3`；原音private ID也加lesson ID。不能覆寫本堂同名檔。 |
| 題目數 | validator接受1–30個concept，但目前排程只取每concept／mode的前3題。製作標準是各3題，不靠第4題增加練習量。 |
| 題型／畫面 | Try支援choice/order/repair；新課三題的stage/type依序為build/order、change/order、fix/repair。scene支援cats/dogs/trees/books/toys/numbers/hats，以及word-card與family-link。 |
| 已發布內容改版 | 不覆寫 `try`；明確授權後追加 `tryRevision: {id, questions:[三題]}`，新版 question ID 與音檔必須不同。任一舊 initial/reviews/deferred/pending ID 會讓該概念繼續原版；尚未開始才用新版。已完成不重開，Say不變。Preview預設Updated，仍可切Original。不能移除被歷史紀錄引用的版本。 |
| 讀取入口 | 三個入口共用 `docs/nativecamp/lessons/catalog.json`，課程登記id/date/teacher；週包另附kind與weekly設定。網址 `?lesson=<id>` 可指定課，直接舊連結不能繞過完成鎖定。首頁優先未完成課與已開放週包；Preview可看全部。新增後核對孩子、preview、家長摘要三者一致。 |
| 進度 | core以 `lessons[lessonId]` 分課存放且保留其他課資料；選課不寫入學習紀錄。不能清空進度、覆蓋舊課ID或重排已作答課的題序。 |
| 既有builder／audit | 9/15的Python builder仍是專用參考，不用它重建新課。各新課與週包以 `source/lesson-source.json` 為真相源，共用 `shared/nativecamp/build_lesson.py` 產生題包與speech jobs，`--check`只比對不覆寫。audit按各manifest檢查，仍保護9/15的35個既有TTS，不能刪掉舊檢查來過關。 |

新來源目錄先設 `.gitignore` 排除 `assets/audio/` 與 `source/private/`。模板和證據不得放家庭token、私人存取網址或完整逐字稿；需要原始內容時用相對路徑指向ignored檔案。

本堂 `--skip-tts` 仍會重寫JSON、jobs與manifest，可能把新文字配上舊MP3的hash。改過spoken／答案時不能靠這個選項宣稱音文一致；須重新產生受影響聲音並核對。只改畫面cue時，先比對修改前後speech工作文字完全相同再保留音檔。不帶 `--teacher` 也不會移除題包的private引用，只會記老師片段未重建；不能把這當作已改為TTS。純查核應優先讀取／比對既有來源，不為檢查而重跑有覆寫效果的main。

## 6. 預覽、驗收、發布、歸檔

每週自動複習另遵循[依實際練習製作 Weekly Review](../shared/nativecamp/weekly-planning.md)：新包的練習窗口為上週日至本週日（不含），發布日為本週日；公開題文不含個人表現，舊週包與進度保持相容。

1. **內容核對**：檢查六題／概念的圖、選項、數量、語法、替代答案及音訊是否一致；換題確實測同一概念。找另一位唯讀reviewer檢查答案歧義與提示是否洩漏目標答案。
2. **不計分預覽**：逐題走Try組句／變換／修正、Say揭曉、問題／答案聲音，確認桌面／窄版；改版時核對Updated／Original。以合成進度檢查跨概念順序、跳過Fix、首次錯誤保留及舊版續作，不修改正式孩子紀錄。
3. **可重建與程式檢查**：比對來源輸出、題包及音訊manifest。沿用實際相關tests；若更動runtime／入口／來源，執行repo的Node與Python gate。測試數量以本次輸出為準，不照抄409／184。
4. **依授權發布**：沿用本次明確授權範圍；需要新版Worker或原音KV時先完成，再發布Pages。只寫該堂指定的內容key，不變更family token或進度key，也不自動替家長勾選活動。private pack最外層是clip ID到payload的對照；每個 `c:nativecamp:audio:<clip-id>` 只存內層 `{contentType, base64}`，不是整包。本機loader沒有遠端部署功能。
5. **上線核對**：記錄commit、CI／Pages結果、必要的Worker version；比對正式資源hash，原音匿名401／已連線播放、私人KV回讀hash。家長入口、課程選擇及摘要必須對同一堂；上線成功不等於iPad或孩子實測通過。
6. **收尾**：在 `learning-tasks/catalog.json` 更新實際狀態與入口並重建索引，該堂 README 保存設計、來源及驗收證據，完成已達標tracker；不要手改 README 產生清單。家長回饋留在模板末段；未提供的結果填「未測」，不把已發布工作繼續列為實作blocker。

命令與本堂正式發布證據見[互動版說明](../../docs-dev/nativecamp-review.md)；私人音訊格式與本機工具見[音訊驗證](source/nativecamp-audio-qa.md)。新課接入的改動以當時code為準，不能直接重跑本堂builder覆寫正式內容。
